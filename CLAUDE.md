# Вудирекс: лендинг и MVP

## Карта проекта

**Что это.** Одностраничный сайт ООО «Вудирекс»: экраны для батарей (МДФ, металл,
массив дерева), металлические корзины для кондиционеров и декоративные изделия.
Рынок Беларусь, язык русский, обращение на «вы».

**Идея.** У Вудирекса нет своего канала заявок, клиенты приходят через чужой сайт.
Лендинг становится первым своим каналом: за десять секунд объясняет, что это, для
кого и как связаться. На нём проверяем спрос: сколько заявок и почём приходит с
контекстной рекламы. У страницы три входа под три типа клиентов: ремонт (частные
люди и офисы), проект и тендер (застройщики), требование закона (старые здания).
Дальше лендинг растёт в MVP по задачам. Первая рабочая часть: калькулятор
«Рассчитать стоимость изделия», который даёт «цену от» по размерам и материалу и
превращает расчёт в заявку.

**Что где лежит.**
- `index.html`: главная. Каждая страница — отдельный HTML, шапка, подвал и форма
  копируются в каждую. Без библиотек, шрифтов и картинок из интернета,
  открывается двойным кликом.
- `assets/style.css`: общие стили всех страниц. Стиль «Мастерская»: графит
  (`--dark`) и медь (`--accent`), тёмные шапка, первый экран и подвал. Место
  под будущий логотип — слева от надписи `.brand`.
- `assets/fonts/`: шрифт Manrope (woff2, кириллица и латиница, лицензия
  `OFL.txt`), подключён через `@font-face` в начале `style.css`.
- `assets/img/<раздел>/`: фото сайта, уменьшенные и без EXIF (геометки
  объектов клиентов). Исходники лежат вне репо, в `Work/StartUp/фото-сайта/`.
  Плитка с фото — класс `.tile.pic`, первый экран с фото — `.hero.hero-photo`.
- `assets/calc.js`: калькулятор страниц экранов по материалу, на главной
  его нет (`CALC_SETTINGS` и чистые функции до первого
  `(function`, ниже UI). Начальный материал — `data-material` на секции `#calc`.
- `assets/site.js`: общее поведение страниц: кнопки `data-ask`, отправка формы
  на почту (mailto), меню шапки, плашка cookies. Сторонние счётчики подключать
  только через список `counters`: он загружается лишь после «Принять». Пока
  список пуст, плашка не показывается и сайт не ставит cookies.
- `politika.html`: политика обработки ПДн (черновик на проверку юристу), ссылка
  на неё под формой заявки и в подвале каждой страницы.
- `docs/superpowers/specs/`: документы дизайна, из них берутся требования к
  каждой части. Есть только на компьютере Саши: в публичный репозиторий не
  попадают (`.gitignore`), хранятся в ветке `backup-with-docs` и приватном
  репозитории `woodirex-docs`. Ветку `backup-with-docs` в `origin` не пушить.
- `docs/agents/`: настройки для скиллов агента (где задачи, какие метки).
- `CLAUDE.md`: этот файл.

**Как сайт публикуется.** GitHub Pages из ветки `main`, корень репозитория.
После `git push` в `main` через минуту-две сайт обновляется по адресу
https://alejandrotelegin1993.github.io/woodirex-landing/. Репозиторий публичный:
всё, что закоммичено в `main`, видят все.

**Как мы работаем.** Одна задача на GitHub = одна новая сессия Claude. Задачи
живут в GitHub Issues этого репозитория. В начале сессии берём один issue,
делаем его, проверяем, коммитим и пушим, закрываем issue. Следующая задача в
следующей сессии, с чистым контекстом.

## Agent skills

### Issue tracker

Задачи живут в GitHub Issues репозитория `alejandrotelegin1993/woodirex-landing`, работа через `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

Стандартные метки: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: один `GLOSSARY.md` и `docs/adr/` в корне (создаются по мере надобности). See `docs/agents/domain.md`.
